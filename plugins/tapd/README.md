# Antumi TAPD 插件

独立的 Antumi 任务来源插件，使用 Antumi Plugin SDK。通过 TAPD 开放平台接口，把 tapd.cn 一个项目里的需求、缺陷或任务同步进收件箱，拉取详情并同步新评论。只读，不修改事项。设计说明见 [DESIGN.md](DESIGN.md)。

> 0.1.0 按官方文档和官方 TAPD MCP 的实现编写，只用真实接口验证过令牌校验，还没有用真实项目联调，待确认的项见 DESIGN.md 第 9 节。

## 在 Antumi 使用

在「设置 → 插件」安装 ZIP 或 `dist/plugin` 目录，然后在「设置 → 集成 → TAPD」填写：

| 设置 | 内容 |
| --- | --- |
| 项目 | 项目 ID，或项目里任意页面的地址 |
| 事项类型 | 需求（默认）、缺陷或任务；要同步多种就添加多个 TAPD 来源 |
| 处理人 | `@me` 表示自己（默认），留空表示所有人，也可填 TAPD 昵称 |
| 状态范围 | 未完成（默认）或全部 |

登录只需要一个个人访问令牌：在 TAPD 的「我的设置 → 个人访问令牌」创建，令牌只显示一次。不需要公司管理员开通 API 账号。也可以用 `ANTUMI_TAPD_TOKEN` 配置。

事项编号形如 `story-1120000000001000001`（TAPD 的长 ID）；手动导入时也可以粘贴事项详情页的地址。每次最多同步 200 项，按更新时间最多扫描 1000 项。详情包含状态、优先级、处理人、创建人、描述、附件文件名和评论；图片保留为链接，附件不下载。

想让事项指派给自己后自动进 Antumi：处理人保持 `@me`，再在 Antumi 里打开「新问题自动排查」。

## 独立开发

```sh
# 在仓库根目录
npm ci
npm run check --workspace antumi-plugin-tapd
```

请求只发往 `https://api.tapd.cn`，不跟随重定向；令牌不出现在错误和日志里。stdout 专供 SDK 使用。
