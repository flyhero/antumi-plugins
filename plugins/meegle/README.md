# Antumi 飞书项目 / Meegle 插件

独立的 Antumi 任务来源插件，使用 Antumi Plugin SDK。通过飞书项目（国内版）或 Meegle（Lark 国际版）的官方 MCP 服务，把一个空间里的工作项同步进收件箱，并拉取详情；也可以把进展写回工作项（改状态、发评论）。设计说明见 [DESIGN.md](DESIGN.md)。

> 0.1.0 按公开资料和第三方的实测记录编写，还没有用真实空间联调，待确认的项见 DESIGN.md 第 9 节。

## 在 Antumi 使用

在「设置 → 插件」安装 ZIP 或 `dist/plugin` 目录，然后在「设置 → 集成 → 飞书项目 / Meegle」填写：

| 设置 | 内容 |
| --- | --- |
| 空间地址 | 在空间里打开任意页面，复制地址。按域名区分飞书项目（`project.feishu.cn`）和 Meegle（`project.larksuite.com`、`meegle.com`） |
| 工作项类型 | 类型 key，逗号分隔，默认 `story,issue`；填错时同步会列出空间里的类型 |
| 筛选条件（MQL） | 只写 WHERE 后面的条件，用字段 key 书写；默认是当前由我负责的工作项；已有筛选条件保留 |

登录只需要一个 MCP Token：在空间所在站点的 `/b/mcp` 配置页，打开个人偏好里的 MCP 开关，数据权限勾选「允许查看数据信息」（要回写再勾选「允许创建或修改数据信息」），复制 `m-` 开头的 Token。不需要在开发者后台建插件。Token 长期有效，在配置页重置即失效。也可以用 `ANTUMI_MEEGLE_TOKEN` 配置。

工作项编号就是工作项 ID；手动导入时可以填 ID、`#ID` 或详情页地址。每次最多导入 200 项，每个类型最多扫描 200 项。详情包含状态、优先级、当前节点、各角色成员、描述、其余字段和最近 20 条评论；图片保留为链接，不下载。

想让工作项在开发确认后自动进 Antumi：筛选条件写 ``array_contains(`current_status_operator`, current_login_user())``（当前负责人是我），再在 Antumi 里打开「事项自动化」。

## 回写

在 Antumi 的任务页可以改工作项的状态、发评论，也可以按规则在任务开始、提交验收、验收通过时自动写。

- **状态**：状态流的工作项列出此刻能流转到的状态；节点流的工作项列出「完成节点「X」」，仅对当前账号独自负责的进行中节点做完成操作，不支持回滚。状态没有通用的分类，规则里的「不倒退」对飞书项目不生效（已终止的工作项除外）。
- **评论**：按 Markdown 发出，飞书项目原样显示；文中的 HTML 注释（飞书项目用它表示 @ 和图片尺寸）会被去掉，所以评论不会 @ 人。返回的链接指向工作项详情页。
- **规则**：「设置 → 集成 → 飞书项目 → 回写规则」按类型独立配置，内置需求和缺陷，自定义类型在同步后出现。没有通用规则；未配置的类型不自动回写。状态名由空间定义，节点流的动作例如「完成节点「开发」」，通常放在提交验收时。所有下拉复用 Antumi 的组件菜单，额度使用短数字框。
- **权限**：MCP 配置页的数据权限要勾选「允许创建或修改数据信息」，改完后重新复制 Token、重新登录。只有查看权限的 Token 照常同步，写入时会报「没有权限」。你在飞书项目里也要有改这个工作项的权限，比如有的空间只允许经办人和报告人改状态。
- 流转需要填必填字段、或节点有投票等不能通过接口填写的字段时会失败，请到飞书项目里手动处理。

> 回写按 meegle-cli 的文档和第三方实测记录编写，还没有用真实空间联调，待确认的项见 DESIGN.md 第 11 节。

## 独立开发

```sh
# 在仓库根目录
npm ci
npm run check --workspace antumi-plugin-meegle
```

请求只发往三个官方域名，不跟随重定向；Token 只发给登录时验证过的站点，不出现在错误和日志里。stdout 专供 SDK 使用。

## 事项自动化与评论闭环

使用 SDK 0.7.0，返回稳定的工作项类型、所属空间、当前账号及当前负责人。负责人来自 `current_status_operator`，节点流在该字段缺失时使用当前节点的结构化 `owners`；参与人和创建者不作为负责人。缺少完整身份时不推断归属。

开启「事项自动化」及自动修复后，中枢分析事项、选择项目和执行 Agent，core 在归属为 sole 等条件满足时创建独立工作区任务，检查通过后提 PR，进入待验收并按类型规则回写。不自动验收、合并 PR 或推进别人的节点。

评论支持分页与同一时间的多条评论去重。初次详情的同步位置覆盖全部已读取评论；后续评论由 Antumi 投递给所关注的会话或关联任务，任务创建后不向中枢重复投递。评论分页重复、缺少稳定编号或创建时间时停止推进同步位置。图片暂以原文链接显示。

状态流没有可靠的通用状态分类，仍报告 unknown（明确终止除外）；评论和节点返回格式尚需真实空间联调，当前验证基于模拟官方 MCP 响应，未实际写入外部空间。
